# 14. The UI is a SvelteKit SPA whose look comes only from the Heaven tokens

- Status: Accepted
- Date: 2026-10-11
- Origin: spec "UI architecture and design tokens" in the first repository
- Issue: #1

## Context

The visual system is the Heaven theme, specified in `docs/themes/heaven.md` against the
component system in `docs/themes/system.md`. Svelte 5 runs inside Tauri with no SSR
([2](0002-desktop-app-with-tauri-and-svelte.md)); data arrives through command wrappers
([4](0004-typed-command-boundary.md)).

## Decision

- SvelteKit with `adapter-static` as an SPA. Routes: `/` (map), `/items`, `/items/[id]`,
  `/layout/[home]`, `/settings`.
- State in `.svelte.ts` modules per domain, using runes; they refetch on change events.
- Components follow the catalogue in `docs/themes/system.md` (ids, parts, states, tokens, motion
  slots) and live in `apps/desktop/src/lib/components/`, named after their id.
- Tokens are generated by `/apply-theme` from the token block in `docs/themes/heaven.md` into
  `apps/desktop/src/lib/theme/tokens.css`, which is never edited by hand. Components use no literal
  colour, font, radius or duration.
- Fonts are self-hosted packages from the theme's Typography table. Icons are the one set the
  theme names (Lucide, `@lucide/svelte`).
- Each colour says one thing: `--accent` (sun-gold) = selection and the primary action, `--focus`
  (blue) = found, live and focus, `--warning` = fragile, `--danger` = needs attention and
  destructive actions. Whether people and ownership get a colour of their own is not decided here.
- Tests with Vitest and Testing Library; `svelte-check` and the tests run in CI.

This rules out SSR, a component library with its own look, and Tailwind utility colours.

## Consequences

- A theme change is a token change, not a component hunt.
- `tokens.css` is a generated copy of the spec; a token changes in the theme file and is regenerated.
- Follow-ups: tokens and base components, icon components, app shell with routes.
